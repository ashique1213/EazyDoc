# Razorpay Payments and Platform Commission Architecture (Day 11)

## 1. Overview

EazyDoc integrates Razorpay to provide secure patient appointment payments and internal platform commission accounting.

The payment system adheres to core security and financial principles:
1. **Never trust frontend amounts or flags**: All payable amounts are derived from server-side consultation fee snapshots (`Appointment.consultation_fee`).
2. **Cryptographic verification**: Payment success is confirmed only after verifying Razorpay's HMAC-SHA256 signature server-side.
3. **Internal accounting allocation**: Platform commission (default 5.00% or clinic-specific override) and clinic net share are internal accounting allocations. Patient checkout displays only the consultation fee without platform commission or clinic share breakdowns.
4. **Strict concurrency & reservation expiration**: Pending reservations hold doctor slots for a configurable window (`PAYMENT_RESERVATION_TIMEOUT_MINUTES`, default 15 minutes). Expired reservations release availability and late payments are protected from creating silent double-booking collisions.
5. **Idempotency & state machine safety**: Duplicate order requests, retried signature verifications, and duplicate/out-of-order webhooks are processed safely without duplicating payments or commission records.

## 3. Database Schema

### A. `Payment` (`payments_payment`)

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique payment transaction identifier. |
| `appointment` | FK (Appointment) | Linked appointment. |
| `patient` | FK (User) | Authenticated patient making the payment. |
| `clinic` | FK (Clinic) | Clinic facility where consultation is scheduled. |
| `gateway_name` | CharField | Gateway identifier (`RAZORPAY`). |
| `gateway_order_id` | CharField (Unique) | Razorpay Order ID (e.g., `order_Kxyz123`). |
| `gateway_payment_id` | CharField (Unique, Null) | Razorpay Payment ID (e.g., `pay_Kxyz123`). |
| `gateway_signature` | CharField (Null) | HMAC-SHA256 signature generated by Razorpay Checkout. |
| `amount` | DecimalField(10, 2) | Trusted consultation amount in INR. |
| `currency` | CharField | Currency code (`INR`). |
| `status` | CharField | `NOT_REQUIRED`, `PENDING`, `AUTHORIZED`, `PAID`, `FAILED`, `REFUND_PENDING`, `PARTIALLY_REFUNDED`, `REFUNDED`. |
| `failure_code` | CharField | Sanitized error code if payment failed. |
| `failure_description` | TextField | Sanitized failure explanation. |
| `idempotency_key` | CharField (Index) | Client request identifier preventing duplicate orders. |
| `paid_at` | DateTimeField (Null) | Timestamp when payment was verified and completed. |
| `created_at` / `updated_at` | DateTimeField | Timestamps. |

### B. `CommissionRecord` (`payments_commission_record`)

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique commission record identifier. |
| `payment` | OneToOne (Payment) | 1:1 linked payment transaction (prevents duplicates). |
| `appointment` | FK (Appointment) | Associated appointment reference. |
| `clinic` | FK (Clinic) | Associated clinic reference. |
| `gross_amount` | DecimalField(10, 2) | Gross consultation fee charged to patient. |
| `commission_rate` | DecimalField(5, 2) | Snapshot of platform commission percentage applied. |
| `commission_amount` | DecimalField(10, 2) | Platform fee: `ROUND_HALF_UP(gross * (rate / 100))`. |
| `clinic_share` | DecimalField(10, 2) | Calculated clinic share: `gross - commission_amount`. |
| `currency` | CharField | Currency (`INR`). |
| `status` | CharField | `PENDING_SETTLEMENT`, `SETTLED`, `REFUNDED`, `CANCELLED`. |
| `settled_at` | DateTimeField (Null) | Timestamp of eventual bank payout settlement. |

**Accounting Invariant**:
$$\text{gross\_amount} = \text{commission\_amount} + \text{clinic\_share}$$

### C. `PaymentWebhookEvent` (`payments_webhook_event`)

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Internal event identifier. |
| `event_id` | CharField (Unique, Null) | Razorpay event identifier (e.g. `evt_Kxyz123`). |
| `event_type` | CharField | Webhook event type (`payment.captured`, `payment.failed`, `order.paid`). |
| `gateway_name` | CharField | Gateway (`RAZORPAY`). |
| `status` | CharField | `RECEIVED`, `PROCESSED`, `FAILED`, `IGNORED`. |
| `payload` | JSONField | Sanitized payload (no prohibited card or auth tokens). |
| `received_at` / `processed_at` | DateTimeField | Processing timestamps. |

### D. `PaymentAuditLog` (`payments_audit_log`)

Append-only log tracking `ORDER_CREATED`, `PAYMENT_VERIFIED`, `PAYMENT_FAILED`, `COMMISSION_CALCULATED`, `WEBHOOK_PROCESSED`, `RECONCILIATION_DISCREPANCY`.

## 4. Platform Commission Calculation & Rounding Policy

### Precedence Rule:
1. **Explicit Custom Override**: If explicitly specified for a settlement.
2. **Clinic-Specific Commission**: If `clinic.commission_rate` is set (e.g., 8.00%).
3. **Platform Default**: `settings.PLATFORM_DEFAULT_COMMISSION_RATE` (5.00%).

### Decimal Precision & Rounding:
- Formula:
  $$\text{commission\_raw} = \text{gross\_amount} \times \left(\frac{\text{rate}}{100}\right)$$
  $$\text{commission\_amount} = \text{quantize}(\text{commission\_raw}, \text{Decimal}("0.01"), \text{ROUND\_HALF\_UP})$$
  $$\text{clinic\_share} = \text{gross\_amount} - \text{commission\_amount}$$
- **Example 1** (Default 5.00% on ₹500.00):
  - Gross: ₹500.00
  - Commission: ₹25.00
  - Clinic Share: ₹475.00
- **Example 2** (5.00% on ₹333.33):
  - Gross: ₹333.33
  - Commission: ₹16.67
  - Clinic Share: ₹316.66
- **Historical Immutability**: `CommissionRecord` stores snapshot values. Modifying a clinic's commission setting in the future never alters past financial transactions.

## 5. API Endpoints

### 1. Create Payment Order
`POST /api/v1/payments/create-order/`
- **Auth**: Authenticated Patient only.
- **Request**:
  ```json
  {
    "appointment_id": "uuid-of-appointment",
    "idempotency_key": "unique-client-key-optional"
  }
  ```
- **Response** (`201 Created`):
  ```json
  {
    "order_id": "order_Kxyz123",
    "amount": "500.00",
    "amount_paise": 50000,
    "currency": "INR",
    "key_id": "rzp_test_placeholder_key_id",
    "appointment_id": "uuid-of-appointment",
    "booking_reference": "EZD-202610-A1B2C3",
    "doctor_name": "Dr. Amit Sharma",
    "clinic_name": "Apollo Care Clinic"
  }
  ```

### 2. Verify Payment Signature
`POST /api/v1/payments/verify/`
- **Auth**: Authenticated Patient only.
- **Request**:
  ```json
  {
    "razorpay_order_id": "order_Kxyz123",
    "razorpay_payment_id": "pay_Kxyz123",
    "razorpay_signature": "hmac_sha256_hex_signature"
  }
  ```
- **Response** (`200 OK`):
  ```json
  {
    "id": "uuid-payment-id",
    "appointment_id": "uuid-appointment-id",
    "booking_reference": "EZD-202610-A1B2C3",
    "appointment_status": "CONFIRMED",
    "amount": "500.00",
    "currency": "INR",
    "status": "PAID",
    "gateway_order_id": "order_Kxyz123",
    "gateway_payment_id": "pay_Kxyz123",
    "paid_at": "2026-10-22T06:30:00Z",
    "created_at": "2026-10-22T06:25:00Z"
  }
  ```

### 3. Patient Appointment Payment Status
`GET /api/v1/payments/appointment/<appointment_id>/status/`
- **Auth**: Appointment owner (patient), clinic owner, or platform admin.
- Strictly excludes commission and settlement metrics from patient responses.

### 4. Razorpay Webhook
`POST /api/v1/payments/webhook/razorpay/`
- **Auth**: `AllowAny` (No JWT required). Verified via `X-Razorpay-Signature` HMAC.
- Handles `payment.captured`, `order.paid`, and `payment.failed`.
- Protects against regression: an older `payment.failed` event cannot regress a `PAID` transaction.

### 5. Clinic Financial Records
`GET /api/v1/payments/clinics/<clinic_id>/financial-records/`
- **Auth**: Authorized Clinic Owner of this specific clinic or Super Admin.
- Returns commission and net clinic share records.

### 6. Admin Update Clinic Commission Rate
`PATCH /api/v1/payments/admin/clinics/<clinic_id>/commission-rate/`
- **Auth**: Super Admin (`is_staff`) only.
- Validates rate between `0.00` and `100.00%`. Audits updates.

## 6. Reservation Expiration & Concurrency Protection

1. When an appointment is booked in `PENDING_CONFIRMATION` state, `reservation_expires_at` is set to `now + 15 minutes`.
2. While `now < reservation_expires_at`, the slot is locked and unavailable to other patients.
3. Once `now >= reservation_expires_at`, the slot is considered expired and becomes bookable by other patients.
4. If a late payment verification arrives for an expired appointment:
   - The transaction locks the doctor schedule and checks for conflicting confirmed bookings.
   - If another patient claimed the slot, the payment is recorded as `PAID` with metadata `late_payment_conflict=True` and flagged for reschedule or refund. It **never** silently creates an overlapping confirmed appointment.
   - If the slot remains unclaimed, the appointment is confirmed safely.

## 7. Future Refund & Settlement Notes

1. **Refunds**:
   - Original `Payment` and `CommissionRecord` records are immutable.
   - A future refund endpoint (`POST /api/v1/payments/<payment_id>/refund/`) will call Razorpay's refund API and create reverse accounting entries.
   - Commission and clinic share reversals must proportionally offset platform receivables and clinic payables.
2. **Clinic Payouts**:
   - `CommissionRecord.status` tracks `PENDING_SETTLEMENT` vs `SETTLED`.
   - When automated or batch bank transfers (or Razorpay Route) are integrated in a future phase, settlements will link to payout reference batches and update `settled_at`.
